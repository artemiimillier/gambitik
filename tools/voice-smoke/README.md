# Живой голос и текстовый разбор — ручная проверка с настоящими ключами

**Только для разработчика, только macOS, стоит денег.** Скрипты для **ручного** прогона против *отдельного* сервера с
ключами из `.env` (`run.mjs`, `conversation.mjs`, `teacher.mjs` — голос, `review.mjs` — текст). Они **не входят** в
`pnpm e2e` (тот всегда беззвучный и бесплатный): одна голосовая сессия ≈ 1 минута ≈ $0.05–0.10, один разбор через
OpenRouter — центы. Скрипты никогда не читают `.env` и не видят ключей: ключи есть только у сервера.

## Правила безопасности (`guard.ts`, проверяется до первого запроса)

- **`--base-url` обязателен** — сервера «по умолчанию» нет: иначе прогон мог бы попасть в рабочий сервер на 8787 и
  записать тестовый профиль «Тигр» в настоящие данные ребёнка. Только `http://127.0.0.1:<порт>` или
  `localhost`, порт указан явно.
- **Порты 8787 и 5173 запрещены** всегда: это сервер ребёнка и Vite, который проксирует на него.
- Сервер должен сам сказать, что его папка данных временная: `GET /api/health` → `"dataDirIsTemp": true` (DATA_DIR
  внутри `$TMPDIR`, `/tmp` или `/private/tmp`). Иначе скрипт не запишет профиль «Тигр» и не сыграет ни одной партии.
- `--out`, `--shots`, `--data-dir` не могут указывать внутрь `data/`.
- Результаты по умолчанию — в `test-results/voice-samples/` (не попадает в git), снимки — в
  `test-results/voice-samples/screenshots/`, черновые файлы (синтезированные реплики «ребёнка», сырые записи) — в
  `$TMPDIR/gambit-voice-smoke/`. Локальную папку для прослушивания `docs/voice-samples/` (в git не попадает) скрипты не трогают (кроме явного `--out`).
- Chromium всегда headless и с `--mute-audio`, голос «ребёнка» — файл (`say -o`), вслух ничего не звучит.

## Подготовка: свой сервер на другом порту

Основной сервер на 8787 отдаёт `apps/web/dist` с диска — поэтому своя сборка идёт во временную папку, а сервер — на
свой порт и со своей временной папкой данных:

```sh
pnpm install
export SMOKE=${TMPDIR:-/tmp}/gambit-smoke            # всё временное — здесь
pnpm --filter @gambit/web exec vite build --outDir "$SMOKE/dist" --emptyOutDir
GAMBIT_API_PORT=8788 GAMBIT_WEB_PORT=5174 GAMBIT_WEB_DIST="$SMOKE/dist" DATA_DIR="$SMOKE/data" \
  LLM_PROVIDER=template CODEX_BIN=off NODE_ENV=production \
  node --env-file-if-exists=.env apps/server/src/index.ts > "$SMOKE/server.log" 2>&1 &
curl -s http://127.0.0.1:8788/api/health        # должно быть "dataDirIsTemp":true
```

`LLM_PROVIDER=template CODEX_BIN=off` — разборы и стратег бесплатные (для `review.mjs` и `teacher.mjs --strategy`
берите `LLM_PROVIDER=auto`). **Бесплатный сухой прогон** (`--dry`): сервер без ключей — добавьте
`OPENAI_API_KEY= OPENROUTER_API_KEY=` перед `node` и уберите `--env-file-if-exists=.env`.

Нужны `ffmpeg`/`ffprobe` (Homebrew), `say` и `afconvert` (есть в macOS) и Chromium от Playwright
(`pnpm exec playwright install chromium`).

## 1. Голос: `run.mjs`

```sh
node tools/voice-smoke/run.mjs --base-url http://127.0.0.1:8788 --layers live,realtime --n 1          # без наушников
node tools/voice-smoke/run.mjs --base-url http://127.0.0.1:8788 --layers live --n 2 --headphones yes  # «в наушниках»
node tools/voice-smoke/run.mjs --base-url http://127.0.0.1:8788 --layers live --n 3 --headphones yes --q1-at 5 --gap 10 --tail 10
```

Что происходит для каждого слоя (`live` = gpt-live-1 через Live API, `realtime` = gpt-realtime-2.1):

1. Голос ребёнка — синтезированный файл, **ничего не звучит вслух**: `say -v Milena -o …aiff` → `afconvert` в WAV
   48 кГц моно → склейка «тишина — вопрос 1 — тишина — вопрос 2 — тишина» (`ffmpeg`). Вопросы:
   «Гамбитик, подскажи, какой ход здесь лучший и почему?» и «А что хочет сделать соперник?».
2. Chromium (headless) запускается с `--use-fake-device-for-media-stream --use-file-for-fake-audio-capture=<wav>`
   и **`--mute-audio`** — динамики молчат, запись идёт с самого MediaStream.
3. В `localStorage` ставится `gambit.e2eVoice=on` — единственный способ включить настоящий голос под автоматикой
   (`apps/web/src/automation.ts`); без него приложение под Playwright всегда беззвучное и бесплатное.
   Там же — настройки: `voice=<слой>`, `micMode=open`, `headphonesConfirmed` по флагу `--headphones`.
   `speechSynthesis.speak` подменён счётчиком, так что запасной голос компьютера тоже не звучит.
4. Тренировочная партия против Пети, 1.e4. Замеряется время от клика до `rtc.connected`, приветствие, два вопроса.
5. Удалённая звуковая дорожка тренера пишется `MediaRecorder` (webm/opus); из журнала `window.__gambitVoiceProbe`
   (`apps/web/src/coach/voiceProbe.ts`, существует только при автоматике **и** `gambit.e2eVoice=on`) берутся
   расшифровки, события канала данных, ответы приложения на делегирование/инструменты.
6. Сессия закрывается сразу (кнопка «Выключить голос Гамбитика»), расход уходит в `POST /api/voice/usage`.

Результаты — в `test-results/voice-samples/`:

| Файл | Что это |
|---|---|
| `<слой>-<n>-dialog.m4a` | **весь разговор**: тренер + наложенные вопросы «ребёнка» — это слушать в первую очередь |
| `<слой>-<n>.m4a` / `.webm` | только голос тренера |
| `<слой>-<n>.json` | отчёт: задержки, расшифровки, делегирование/инструменты, проверка «только по-русски», эхо-защита (mute/unmute), перебивание, ошибки, полный журнал зонда |

Флаги: `--layers`, `--n` (номер образца), `--headphones yes|no` (по умолчанию `no`), `--q1-at` (секунда первого
вопроса после открытия микрофона, по умолчанию 26), `--gap` (пауза между вопросами, 24), `--tail` (тишина в конце, 24),
`--base-url` (адрес сервера, обязателен), `--out`, `--work`, `--headed`.

## 1б. Живой разговор («Поговорить»): `conversation.mjs`

Проверяет, что разговор открывается сам в начале партии, тренер отвечает без кнопок,
говорит **своими словами**, а шахматные факты берёт у движка. Сервер — как в «Подготовке» (шаблонные разборы, чтобы не
тратить деньги на ИИ-разбор). `--data-dir` — та же папка, что `DATA_DIR` сервера (из неё читается журнал партии, G):

```sh
C="node tools/voice-smoke/conversation.mjs --base-url http://127.0.0.1:8788 --data-dir $SMOKE/data"
$C --layer live --n 1                              # сценарии A–E + G
$C --layer live --n 2                              # F: то же ещё раз — слова должны быть другими
$C --layer live --n quiet --scenario quiet         # «Тихо»: сам говорит только важное
$C --layer realtime --n 1 --scenario short         # gpt-realtime-2.1: A, B, C, E, G
$C --layer live --n dry --dry                      # БЕСПЛАТНО: сервер без ключа, проверка самого скрипта
```

Как «говорит ребёнок»: не зацикленный WAV-файл, а подменённый в этом браузере `getUserMedia` — поток WebAudio с
тихим «шумом комнаты» (≈ −54 dBFS), в который скрипт проигрывает реплику (`say -v Milena` → WAV) **в нужный момент**:
после того как тренер замолчал, после хода на доске. Шум обязателен: с цифровой тишиной в поток не идут аудиокадры, и
модель Live «замирает» (это свойство тестового стенда, не приложения).

Сценарий (`full`): мастер «Играть → 10 минут → Петя → Белые» (клик — жест пользователя) → **A** разговор открылся
сам, время до «Слушаю» → **B** «Привет, Гамбитик! Как дела?» → ход 1.e4 → **C** «А что хочет сделать соперник?»
(ответ сверяется с фактами приложения: какие клетки назвал тренер) → **D** «А если я пойду конём на эф три?» (вызвана
ли проверка хода; не назван ли лучший ход по Stockfish) → **E** настоящий зевок ферзя (находится движком в странице):
предложение вернуть ход своими словами — сходство с шаблоном (Жаккар по словам) < 0,5, есть смысл «вернуть/подумать»,
лучший ход не назван → «Верну ход и подумаю» → ещё один нормальный ход → сдача → **G** журнал на диске: слова
ребёнка и то, что тренер сказал на самом деле. Сессия закрывается кнопкой «Поговорить»; жёсткий предел `--max-seconds`.

Результаты: `test-results/voice-samples/conv-<слой>-<n>.m4a` (голос тренера), `…-dialog.m4a` (тренер + реплики
«ребёнка»), `…json` (проверки A–G/quiet, задержки, расшифровки, вызовы инструментов, журнал зонда, RTP-пакеты
микрофона), снимки `test-results/voice-samples/screenshots/conv-<слой>-<n>-{listening,takeback,result}.png` (`--shots`).

## 1в. Режим «Учитель» с живым голосом: `teacher.mjs`

Проверка §8.3 `docs/TEACHER-MODE.md`: говорит ли модель `gpt-live-1` советы учителя своими словами и честно.
Сервер — как в «Подготовке» (прод-режим, временная папка данных, шаблонные разборы):

```sh
node tools/voice-smoke/teacher.mjs --base-url http://127.0.0.1:8788 --n 1          # платно, ≈ 5–6 минут сессии ≈ $0,25–0,30
node tools/voice-smoke/teacher.mjs --base-url http://127.0.0.1:8788 --n dry --dry  # БЕСПЛАТНО: сервер без ключа
node tools/voice-smoke/teacher.mjs --reanalyse test-results/voice-samples/teacher-live-1.json   # без сервера: пересчитать проверки
```

Сценарий: мастер «Играть → 10 минут → Петя → «Учитель» → Белые» (ступень 1), разговор открывается сам. Около десяти
ходов «ребёнка»: чаще всего — зелёная стрелка (её берём из события `teachTurn` в журнале зонда), с 3-го хода через ход —
по одному особому ходу: **зевок** (ход фигурой, который стоит ≥ 25 % шансов, — чтобы сработало предложение вернуть ход;
его принимаем), **свой ход** не хуже совета и **свой ход слабее** (60–220 сантипешек). «Сокровище» — ждём раскрытия
(10 с). После 1.e4 и ответа бота «ребёнок» спрашивает голосом **«А почему не ферзём?»**. В конце — сдача.

Проверки (`checks` в `.json`):

| Проверка | Как считается | Порог |
|---|---|---|
| `voicedShare` | доля реплик учителя (`teachTurn`, `teachReaction`, учительское предложение вернуть ход), которые модель произнесла сама (`say.done: spoken` с непустой расшифровкой) | ≥ 90 % |
| `namedMoves` | каждое предложение расшифровки → `parseSpokenMove`; клетка хода должна быть в брифе (строка «Можно назвать» или факты: ходы и угрозы соперника); `squaresNotInBrief` — все клетки, которых нет в брифе | 0 нарушений |
| `sentences` | предложений в реплике стиля `full` | ≤ 4 в ≥ 90 % |
| `latin` | латинские буквы в расшифровках тренера | 0 |
| `variety` | Жаккар по словам соседних реплик `teachTurn` | < 0,5 |
| `latency` | от появления хода бота в списке ходов до события `teachTurn` (приложение) и до первого звука модели | приложение ≤ 1,5 с |
| `openingPlan` | что модель сказала в первой реплике партии (план дебюта) — цитата | — |
| `whyQueen` | ответ на «а почему не ферзём?»: намерение `whyNot`, факты `compareMove`, слова модели, задержка | — |

Результаты: `test-results/voice-samples/teacher-live-<n>-dialog.m4a` (тренер + вопрос «ребёнка»), `…json` (проверки,
реплики с брифами и расшифровками, ходы, журнал зонда), снимок `test-results/voice-samples/screenshots/teacher-live-<n>-game.png`.

## 1г. «Учитель»: стратегия и краткость — `teacher.mjs --strategy`

Проверяет, что учитель говорит коротко, не читает часы, в каждой партии предлагает новую стратегию и что её составляет
умная модель. Сервер — как в «Подготовке», но с **настоящим стратегом** (`LLM_PROVIDER=auto` вместо `template`, без
`CODEX_BIN=off`: Codex → OpenRouter → OpenAI API):

```sh
T="node tools/voice-smoke/teacher.mjs --base-url http://127.0.0.1:8788"
$T --strategy --server-log "$SMOKE/server.log"                   # платно, ≈ 8–10 мин сессии
$T --strategy --dry                                              # БЕСПЛАТНО: сервер без ключей
$T --strategy --no-mic --games w --moves 3 --prefix nomic-live   # микрофон ЗАПРЕЩЁН
node tools/voice-smoke/teacher.mjs --reanalyse test-results/voice-samples/<отчёт>.json   # без сервера: пересчитать метрики
```

`GAMBIT_WEB_DIST` (по умолчанию `apps/web/dist`) — какую сборку отдаёт сервер. `--no-mic`: без поддельного микрофона и без
разрешения — тренер всё равно должен говорить (заглушка-дорожка с комфортным шумом), а `voiceSessionCalls` в отчёте
считает `POST /api/voice/live|realtime` — больше одного на партию означает петлю переподключений.

Сценарий: три партии в «Учителе» против Пети (10 минут; `--games w,w,b`), в каждой ≈ 8 ходов «ребёнка» (`--moves 8`) —
зелёная стрелка, один раз (`--deviate-at 3`, 4-й ход) свой ход не хуже совета. У каждой партии своя страница: своя
голосовая сессия, свой журнал зонда и своя запись. Предел денег — `--game-max-seconds` (330) на партию.

Проверки (`checks` в `strategy-live-<n>.json`, сводка — `strategy-live-summary.json`):

| Проверка | Как считается | Цель |
|---|---|---|
| `intro` | первая реплика после нажатия цвета — `gameStart` учителя с названием стратегии (в шаблоне и в словах модели) | да |
| стратегии разные | `strategyId` партий | все разные |
| `brevity` | слова и предложения каждой реплики учителя (модель; в сухом прогоне — шаблон) | ≤ 25 слов и ≤ 2 предложения в ≥ 90 % |
| `brevity.over` | каждая реплика сверх бюджета: что модель добавила (`opponent`, `praise`, `question`, `topic`, `plan`, `blueArrow`, `elaboration`) и было ли это в брифе (`inBrief`); сводка — `overByCategory` | — |
| `clock` | «минут», «секунд», «часы»… в расшифровках тренера и в шаблонах; «время» — отдельно | 0 |
| `planReasons` | реплики со словами «план / стратегия» (цитаты) | > 0 |
| `replans` | каждый `POST /coach/replan`: провайдер, задержка, стал ли его ход зелёной стрелкой, попал ли новый план в следующий бриф; строки журнала `coachSaid {kind:'replan'}` | — |
| `latency`, `voicedShare` | как в §1в | ≤ 1,5 с; ≥ 90 % |
| стоимость | секунды Live за партию (`/api/voice/usage`) × $0,05/мин + вызовы OpenRouter | — |

## 1д. «Учитель» в 5-минутной партии: `teacher.mjs --blitz5`

«Учитель» работает и в партии на 5 минут, а **часы ребёнка стоят, пока Гамбитик говорит**.
Сценарий для живой проверки: мастер «Играть → 5 минут → Петя → «Учитель» → Белые», одна партия (`--games w`), восемь
ходов «ребёнка» (`--moves 8`): зелёная стрелка, 3-й ход (`--blunder-at 2`) — настоящий зевок, предложение вернуть ход
принимаем, дальше один свой ход не хуже совета (`--deviate-at 3`). Сервер — как для `--strategy`.

```sh
$T --blitz5 --server-log "$SMOKE/server.log"     # платно, ≈ 4–6 мин сессии ≈ $0,20–0,30
$T --blitz5 --dry                                # БЕСПЛАТНО: сервер без ключей (шаблоны, голос браузера заглушён)
$T --blitz5 --games w,b                          # две партии: стратегии должны различаться
```

Проверки (`checks` в `blitz5-live-<n>.json`, сводка — `blitz5-live-summary.json`) — все проверки `--strategy`
(`intro` — первая реплика = стратегия одной строкой, `brevity` — ≤ 25 слов и ≤ 2 предложения, `clock` — ни «минут», ни
«секунд» в словах тренера, `planReasons`, `replans`, `latency`) и сверх них:

| Проверка | Как считается | Цель |
|---|---|---|
| `clockWhileSpeaking` | часы ребёнка (`[data-side="child"] [role="timer"]`, `data-running` / `data-paused`) записываются при каждом изменении и сравниваются с отрезками, когда тренера слышно (`rtc.coach-audible`) на ходу ребёнка; `leakMs` — сколько его часы шли, пока тренер говорил; `holds` — сколько раз часы вставали | `leakShare` ≤ 10 % (сухой прогон: `holds` > 0) |
| `takeback` | зевок, через сколько появилось предложение (`offerLatencyMs`), шаблон и слова модели, состояние часов ребёнка во время предложения, предложение принято | предложено, часы ребёнка не идут |

## 2. Текст: `review.mjs`

```sh
node tools/voice-smoke/review.mjs --base-url http://127.0.0.1:8788     # сервер с LLM_PROVIDER=auto
```

Отправляет короткую законченную партию (фикстура сервера `apps/server/src/testing/fixtures.ts`: детский мат с одним
возвращённым зевком) как обычный клиент — **без** заголовка автоматики, ждёт фоновый разбор и печатает, какой провайдер
его написал (`codex` → `openrouter` → `openai-api` → `template`). Первые 15 строк markdown пишутся в
`test-results/voice-samples/review-sample.md` (`--out`).

Удалить партию через API нельзя (такого маршрута нет) — поэтому `guard.ts` пускает только на сервер с временной `DATA_DIR`.
