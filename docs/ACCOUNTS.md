# Аккаунты публичного сайта

Самый простой вход, чтобы другие дети могли заниматься и их прогресс сохранялся: ник + пароль, без почты.
Включается только на сервере (`GAMBIT_ACCOUNTS=1`); дома (`Шахматы.command`) приложение работает без
входа.

## Что видит семья

- Сайт открывается на «двери»: **Войти** / **Новый ученик** / «Забыли пароль?».
- **Новый ученик**: ник (он же имя в игре — не настоящее имя), пароль (не меньше 8 символов) дважды, **код
  приглашения** (его даёт тот, кто ведёт сайт), мальчик / девочка (только для русской грамматики), ступень 1–10.
- После регистрации **один раз** показывается **код восстановления** `XXXX-XXXX-XXXX-XXXX` — записать или
  сфотографировать. По нему можно задать новый пароль («Забыли пароль?»); после этого показывается новый код, старый
  перестаёт работать, все входы на других устройствах закрываются.
- В **Настройках** (за родительским замком) — карточка «Аккаунт»: кто вошёл, «Выйти», «Удалить аккаунт…» (с паролем;
  удаляются аккаунт, все партии, дневник, успехи, настройки — навсегда).
- Один аккаунт = один ученик. Второй ребёнок на том же компьютере регистрируется отдельно: при выходе всё, что браузер
  помнил о ребёнке, удаляется из браузера, и чужого другой ребёнок не увидит.

## Что хранится (минимум данных)

| Где | Что |
|---|---|
| `DATA_DIR/accounts.db` | ник (для входа), хэш пароля и кода восстановления (scrypt с солью), даты создания и входа; сессии и «знакомые устройства» — только sha256 токена |
| `DATA_DIR/users/<id>/` | всё остальное ребёнка — своя SQLite и свои файлы, как `data/` дома: профиль (ник, м/д, ступень, успехи), партии, дневник, задачи, «Мои успехи», и то, что браузер помнит о ребёнке: книга фраз урока, настройки голоса и звука, карточки учителя, недоигранная партия (`/api/account/state`) |

Почты, настоящих имён, телефонов, IP-адресов в базе нет. Адрес клиента используется только в памяти — для ограничения
попыток входа.

## Безопасность

- **Пароли**: scrypt (N = 2¹⁵, r = 8, p = 1), случайная соль, сравнение за постоянное время; принимаются только эти
  параметры. Не меньше 8 символов; самые угадываемые пароли («12345678», «qwerty123», «пароль123», «йцукенгш»,
  «шахматы123», даты из цифр …) не принимаются. Неизвестный ник и неверный пароль — одинаковый ответ и одинаковое время.
- **Сессия**: случайный токен 256 бит в cookie `HttpOnly`, `SameSite=Lax`, на https — `Secure` и имя `__Host-gambit`;
  в базе только его sha256; 30 дней, продлевается раз в сутки при использовании, но не дольше 90 дней от входа. Новый
  вход в том же браузере закрывает старую сессию. Выход, смена пароля по коду и удаление аккаунта закрывают сессии.
  Код восстановления — одноразовый (два запроса с одним кодом одновременно: срабатывает один).
- **Знакомое устройство**: после удачного входа, регистрации или восстановления браузер получает вторую cookie —
  `HttpOnly`, `SameSite=Lax`, на https `Secure` и `__Host-gambit-device`; в базе только sha256 токена, число устройств
  на аккаунт ограничено, все забываются при восстановлении по коду, при сбросе пароля администратором и с удалением
  аккаунта. Вход с устройства, знакомого этому аккаунту, не упирается в лимит попыток на ник — незнакомец, знающий
  ник, не может этим не пускать ребёнка. Один браузер помнит несколько аккаунтов (братья и сёстры на одном планшете).
- **Разделение данных**: запрос аккаунта обслуживается **его собственным** контекстом сервера — своя база и своя
  папка; чужих данных нет ни в одной таблице и ни в одном пути, доступном обработчику. Путь строится только из id
  аккаунта (16 hex). Контекст никогда не закрывается под работающим запросом. Проверено тестами: чужую партию нельзя
  получить ни списком, ни по id, ни журнал, ни разбор.
- **Общий компьютер, две вкладки**: страница повторяет свой аккаунт в каждом запросе; вкладка ребёнка, который вышел в
  другой вкладке, получает `account-changed` и перезагружается, а не пишет в аккаунт следующего ребёнка. На экране
  входа в браузере не остаётся ничего от прежнего ребёнка.
- **Перебор**: попытка считается ДО проверки пароля (параллельные запросы не обходят лимит). Лимиты попыток входа — на
  ник и на адрес (IPv6 — по подсетям), отдельные лимиты на неверные коды приглашения, регистрации и восстановление;
  общий лимит неверных кодов никогда не блокирует верный код. Ответ 429 с `Retry-After`. Число одновременных проверок
  пароля ограничено — дальше 503 «сервер занят», массовые попытки не останавливают сервер. Попытка, которую сервер не
  проверил, не списывается с лимита. Точные числа — в `apps/server/src/accounts/limiter.ts` и `routes.ts`.
- **Код приглашения** сравнивается без учёта регистра букв, пробелов и дефисов. `set-invite.sh --generate` делает
  случайный код из 20 знаков без похожих символов (`XXXXX-XXXXX-XXXXX-XXXXX`, ~92 бита) — подобрать его нельзя.
- **Диск общий**: число изменений и партий на аккаунт ограничено; при малом свободном месте новые данные не
  записываются; регистрация закрывается на `GAMBIT_MAX_ACCOUNTS` аккаунтах.
- **Процессор общий**: размер партии (полуходы, длина PGN, число и размер событий) и тела запроса ограничены с большим
  запасом над настоящими партиями; чтения и пересчёты профиля на аккаунт ограничены по частоте.
- **CSRF**: `SameSite=Lax` + проверка `Origin` сервером + только JSON в запросах, меняющих данные.
- **Деньги**: с аккаунтами сервер сам выключает всё платное и генеративное, что бы ни было в настройках (ИИ, ключи,
  codex, дозапись голоса); запросы записи — 503, переключатель — 403, траты никому не показываются.
- **Незнакомцу** `/api/health` отвечает только «сайт работает».
- **CSP**: на публичном сайте страница ходит только на свой сервер (`connect-src 'self'`, без api.openai.com — живого
  голоса там нет); домашний сервер оставляет OpenAI для живого голоса.
- **Журнал сервера**: одна строка на каждую попытку регистрации и входа — `[accounts] register → 201`,
  `→ 403 bad-invite`, `→ 429 too-many-attempts`, `→ 400 password-short`, `→ 400 invalid-body` … — без ника, пароля,
  кода и адреса. Видно, дошёл ли запрос с телефона семьи и что ему ответили: `docker logs gambitik | grep accounts`.

## Открытая регистрация

`GAMBIT_OPEN_REGISTRATION=1` в `app.env`: регистрироваться может кто угодно, без кода приглашения (поле кода на
странице не показывается; присланный код не проверяется). Вместо кода от скриптов защищают:

- **задачка (proof of work, `apps/server/src/accounts/pow.ts`)**: страница берёт `GET /api/auth/challenge` и, пока
  ребёнок заполняет форму, подбирает число, чтобы sha256(`задача:число`) начинался с 16 нулевых битов (≈65 000 попыток,
  секунда-две на телефоне; `GAMBIT_POW_BITS`, 0 = выключено). Задача подписана секретом сервера, живёт 15 минут, одна
  задача = один аккаунт (ошибка в форме её не тратит). Одной семье незаметно, тысяче фальшивых аккаунтов — дорого;
  никаких сторонних капч и отправки данных наружу;
- **скрытое поле-ловушка** `website`: человек его не видит, скрипт, заполняющий всё подряд, заполняет;
- неверная/чужая задача и ловушка считаются как неверный код приглашения (тот же лимит на адрес);
- обычные лимиты: регистрации с адреса и на весь сайт, всего аккаунтов `GAMBIT_MAX_ACCOUNTS`, диск и записи на аккаунт.

У таких аккаунтов метка «открытая» (в админке — «без кода»). Коды семей и общий код продолжают работать, если
открытую регистрацию выключить.

## Коды приглашения для семей

Кроме общего кода (`GAMBIT_INVITE_CODE` в `app.env`, `set-invite.sh`) у каждой семьи или группы может быть свой:

    deploy/docker-ssh/invite.sh new 'Семья Ивановых' [3]   # новый код XXXXX-XXXXX-XXXXX-XXXXX, показан один раз
    deploy/docker-ssh/invite.sh list                        # коды: открыт ли, сколько учеников пришло по каждому
    deploy/docker-ssh/invite.sh off 'Семья Ивановых'        # больше никто не зарегистрируется (аккаунты остаются)

В `accounts.db` хранится только sha256 кода (в сравниваемом виде: регистр, пробелы и дефисы не важны), метка, сколько
раз использован и сколько можно. Использование берётся до создания аккаунта и возвращается, если аккаунт не создан
(ошибка в форме, занятый ник, сервер занят). У аккаунта записана метка кода (`invite_label`; «общий» — общий код,
пусто — метки нет); админка показывает её у каждого ученика и сводку по кодам. Регистрация открыта, пока есть
общий код или хоть один открытый код семьи. Общий код закрывается `set-invite.sh --off` — после этого приходят только
по кодам семей.

## Админка (`/admin`)

`https://<сайт>/admin` — сколько учеников, кто сейчас на сайте и на каком экране (играет партию, решает задачи …),
партии и задачи по часам за 48 часов, контроль времени, боты, итоги партий, ступени, таблица учеников (ник, ступень,
партии, победы/ничьи/поражения, задачи, рейтинг, когда был, когда зарегистрировался). Обновляется сама каждые 15 с.

- Открывается только аккаунтам из `GAMBIT_ADMIN_LOGINS` (ники через запятую, в `app.env`:
  `deploy/docker-ssh/set-admin.sh 'МойНик'`); всем остальным `/api/admin/stats` — 404, без входа — 401.
- «Кто сейчас на сайте»: страница вошедшего ребёнка раз в минуту (и при смене экрана) шлёт `POST /api/presence
  {screen}` — только имя экрана; сервер держит это в памяти, перезапуск забывает. Онлайн = отметка за 2,5 минуты.
- Остальное читается из баз аккаунтов только на чтение, с кэшем 5 с; пароли, хэши, коды восстановления, содержимое
  партий и мысли ребёнка в админку не попадают.

## Резервные копии и обслуживание

Ночная копия данных (`deploy/docker-ssh/backup.sh`, по cron на сервере): SQLite-базы копируются согласованно
(`VACUUM INTO` внутри работающего контейнера), остальные файлы — как есть. Восстановление, выгрузка копий с сервера,
коды приглашения и помощь семье с забытым паролем (`admin.ts reset-password`) — в `deploy/docker-ssh/README.md`.
