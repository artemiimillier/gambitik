# 08. Детский UX, маскот-тренер и персонажи-боты

Целевая аудитория: ребёнок ~6–10 лет, русскоязычный, уже знает ходы фигур; цель — системный рост. Платформа: локальное web-приложение на macOS (значит, основной ввод — мышь/трекпад, а не палец; это важно, см. раздел 1.3).

Что не удалось подтвердить открытым источником или экспериментом, помечено **НЕ ПРОВЕРЕНО**. Версии и лицензии пакетов — по `npm view`, `npm pack` (типы из тарболов) и GitHub API; прототип маскота проверен запуском в Chromium 152; коэффициенты контраста посчитаны скриптом.

---

## 0. Короткие выводы (TL;DR)

1. **Маскот делаем полностью в коде: inline SVG + CSS custom properties + CSS keyframes** (опционально `motion@13.4.0` для последовательностей). Прототип (≈70 строк SVG + ≈40 строк CSS) отрендерен в 7 состояниях в WebKit и проверен вживую в Chromium — подход рабочий, дизайнер не нужен. Rive технически лучше (на нём сделаны персонажи Duolingo), но **с октября 2025 года бесплатный план Rive не экспортирует `.riv`** (нужен Cadet, $9/мес при годовой оплате; уже сделанные экспорты остаются вашими навсегда, т.е. хватит и одного оплаченного месяца) и персонажа всё равно надо рисовать и риггить в редакторе руками — это не «fully in code». Оставляем Rive как апгрейд «когда появится дизайнер», за тем же интерфейсом `pose + mouthLevel`.
2. **Рот маскота** — один параметр `--mouth` (0..1) из RMS-амплитуды удалённого WebRTC-трека через `AnalyserNode`. Звук играет обычный `<audio>` (это заодно обходит давнюю особенность Chromium с «немым» remote-stream в WebAudio и сохраняет эхоподавление), анализатор — только «отвод», к `destination` не подключается. Фолбэк — события `output_audio_buffer.started/stopped` (WebRTC-only) + псевдослучайное «хлопанье».
3. **Победитель среди маскотов — жеребёнок-конь «Гамбит» (ласково «Гамбитик»)**. Концепт пешки «Пешик» не выбрасываем: он становится метафорой прогресса — «Путь пешки» (8 горизонталей = 8 ступеней программы, в конце превращение в ферзя).
4. **Лестница из 8 ботов**: Петя (~300) → Соня (~500) → Гриша (~700) → Саша (~900) → Вика (~1100) → Лёва (~1400) → Ника (~1800) → Дима (2500+). У каждого — возраст, характер, стиль игры как «модель ошибок», аватар-спека, реплики. Все реплики написаны **без глаголов прошедшего времени в адрес ребёнка** (в русском они выдают пол) — пол ребёнка задаётся в профиле, и только LLM-тренер его использует.
5. **Награды без тёмных паттернов**: никакого «сгорающего» стрика, стыдящих сообщений, пушей, лутбоксов и валюты. Вместо этого — недельная цель «4 дня из 7» без штрафа, звёзды за *усилие* (разбор партии, возврат хода с улучшением, подумал над критическим ходом), конечный альбом наклеек, косметика для Гамбита за вехи.
6. **Ассеты**: фигуры по умолчанию — `rhosgfx` (**CC0**, мягкие, с толстым контуром) + «турнирная» тема `chessnut` (**Apache-2.0**) или `cburnett` (**GPLv2+**). Популярные `staunty`, `fresca`, `horsey`, `anarcandy` и др. — **CC BY-NC-SA** (нельзя в коммерцию). Шрифт — **Nunito** (OFL, есть кириллица, вариативный). **Fredoka, Baloo 2, Quicksand, Comic Neue, Varela Round кириллицу не поддерживают.** Звуки: стандартный набор lichess — **non-free** (нужно разрешение), наборы `sfx/piano/nes/futuristic` — AGPLv3+; безопасный выбор — паки Kenney (**CC0**).
7. **Приватность**: по гайду OpenAI «Under 18 API Guidance» нельзя обрабатывать персональные данные детей до 13 лет без Zero Data Retention. Голос ребёнка — персональные данные. Это открытый вопрос, который нужно решить до включения облачного голоса (см. раздел 10).

### 1.2 Исследования NN/g (UX для детей 3–12)

Подтверждено по двум статьям Nielsen Norman Group:

- **Нельзя дизайнить «для детей вообще»**: минимум три группы — 3–5, **6–8 (начинающие читатели)**, **9–12**. Дети резко отвергают то, что выглядит рассчитанным на класс младше («это для малышей»). Наш диапазон 6–10 пересекает границу → нужен **«взрослеющий» интерфейс**: тон Гамбита, длина реплик и плотность UI зависят от возраста/уровня в профиле.
- **Чтение**: младшие читают медленно, длинные инструкции пропускают *все* дети. Кегль: ~14pt для младших, 12pt для старших (у нас: базовый 18–20 px, кнопки 20–24 px).
- **Анимация и звук детям нравятся** и ожидаются (в отличие от взрослых).
- **Скролл**: для младших избегать. Экраны — в один вьюпорт.
- **Моторика**: до 9 лет трудны **перетаскивание курсором на большое расстояние** и скролл мышью/трекпадом; трекпад предпочитали 3–5-летки (рука не обхватывает мышь), 7-летки при наличии тачскрина бросали и мышь, и трекпад, а 8-летки для перетаскивания и скролла сами переходили на мышь. **Поддерживать и tap-tap, и drag** для одного действия. Для тач-экранов — цель **≥ 2×2 см** (вчетверо больше взрослой 1×1 см).
- Дети не отличают рекламу от контента → никакой рекламы и внешних ссылок в детской зоне.

**Следствие для доски**: обязательный режим «клик по фигуре → клик по клетке» с подсветкой возможных ходов большими точками; drag — как альтернатива. В `react-chessboard@5.12.1` (MIT, peer React 19) есть и `onSquareClick`, и `onPieceDrop`, и `allowDragging`, и `squareStyles`, и `arrows` (зависимости — `@dnd-kit/core`, `@dnd-kit/modifiers`) — проверено по `.d.ts` из npm-тарбола.

### 1.4 Петли вознаграждения без тёмных паттернов

| Делать | Не делать |
|---|---|
| **Недельная цель** («занимаюсь 4 дня из 7»), календарь с отметками, пропуск ничего не ломает | «Сгорающий» стрик, заморозки за валюту, счётчик потери |
| Звёзды **за усилие**: разобрал партию, вернул ход и нашёл лучший, подумал ≥ N секунд над критическим ходом, решил задачу со 2-й попытки | Награды только за победы (провоцирует игру со слабыми ботами) |
| **Конечный альбом наклеек** (известно, что и за что получишь) | Лутбоксы, случайные награды, «крутилки» |
| Косметика для Гамбита за вехи (шарф, медаль, корона на 8-й ступени) | Магазин, любая валюта, «почти хватило» |
| Естественные точки остановки: после разбора — «На сегодня отлично! Продолжим завтра?» | Автозапуск следующей партии, таймеры «вернись через 2 часа», пуши |
| Сообщения о прогрессе: «47 ходов без зевков — твой рекорд» | Стыд и вина («Гамбит грустит без тебя») |
| Счёт против каждого бота + «продержался дольше, чем в прошлый раз» против сильных | Публичные лидерборды |

Принципы «стрик без стыда» (UX Magazine): отделять стрик от дневной цели, grace-периоды, «earn back» усилием, а не оплатой, формулировки про долгий тренд, а не про срыв.

### 1.5 Длина сессии

- AAP в феврале 2026 (первое обновление с 2016) **убрала фиксированные лимиты по времени** для школьников и перешла к подходу «качество/контекст/не вытесняет ли сон и движение» (рамка «5 C»). Значит, жёсткой «научной» цифры нет.
- **Проектное решение (эвристика, НЕ ПРОВЕРЕНО исследованиями):** «Тренировка дня» ≈ 15–20 минут = разминка 3 задачи (3 мин) → одна партия 5 или 10 мин → разбор 3 момента (3–4 мин). Мягкое предложение перерыва на 25–30-й минуте («Я подустал, и глазкам пора отдохнуть»), жёсткий лимит задаёт родитель. Уроки Story Time Chess с живым тьютором длятся 45–60 мин — но это с человеком, не с экраном.

### 1.6 Интерфейс «без чтения»

- Всё важное Гамбит **проговаривает**; текст дублирует (короткие субтитры в «облачке» — заодно тренировка чтения и доступность).
- Кнопка = иконка + 1–2 слова. Русские слова длинные → закладывать ширину, не переносить, не писать КАПСОМ.
- Сила бота — «пешечки» 1–8 и цвет ступени; число Elo — мелко, для родителя и старших.
- Оценка хода — форма + цвет + звук: ✓ зелёный кружок, «!» звезда, «?» оранжевый треугольник (не только цвет).
- Запись партии — фигурками (♘f3), а не буквами «Кf3»; полная нотация включается с определённой ступени программы (это навык, нужный для роста).

### 1.7 Звуковой дизайн

- Ход/взятие/шах — короткие (< 300 мс), «деревянные», различимые на слух; ошибка — мягкий «упс», не зуммер; победа — джингл ≤ 2 с; поражение — нейтральный короткий звук, без «грустного тромбона».
- **Голос главнее**: когда Гамбит говорит или слушает, SFX приглушаются до ~30 % (ducking через общий `GainNode`), фоновой музыки по умолчанию нет (микрофон её «слышит», а распознавание детской речи и так хуже взрослой).
- Раздельные ползунки «Голос / Звуки» в родительских настройках; у всего звукового есть визуальный эквивалент.

### 1.8 Голосовой UX для ребёнка

- Распознавание детской речи стабильно хуже взрослой (выше WER; сильнее всего у 4–7 лет, выравнивается к 12–13) — данные из обзорной выдачи (The Learning Agency, arXiv), сами статьи не открыты. Следствия: Гамбит **не должен зависеть от точного понимания** — критичные действия (вернуть ход, сдаться, выбрать бота) всегда дублируются кнопками; при неразборчивом вводе — «Я не расслышал, скажи ещё разок или нажми кнопку» (в гайде OpenAI советуют слово *unintelligible* в правилах про неразборчивый звук).
- Режим микрофона по умолчанию: **«нажми, чтобы Гамбит слушал»** (тумблер, уши маскота встают торчком = «слушаю»). «Свободный разговор» с server/semantic VAD — опция для наушников: из колонок модель слышит саму себя и SFX.
- **Сон = отключённая realtime-сессия.** 60–90 с тишины → Гамбит зевает и засыпает (соединение закрыто, деньги не тратятся: `gpt-realtime-2.1` / `gpt-realtime-2` стоят $32/1M входных и $64/1M выходных аудио-токенов, `gpt-realtime-2.1-mini` — $10/$20, `gpt-live-1` — $0.05 за минуту сессии с посекундной тарификацией; всё это API-биллинг, см. разделы 3.4 и 10). Клик по спящему → просыпается, машет, сессия поднимается заново. Клик нужен и технически: `AudioContext` и микрофон требуют пользовательского жеста.

### 2.2 Рекомендация

**Фаза 1 (сейчас): inline SVG + CSS.** Один React-компонент `<Mascot pose mouthRef/>`; позы — атрибут `data-pose`; рот — CSS-переменная, которую `requestAnimationFrame` пишет **напрямую в DOM через ref** (не через React state — 60 обновлений в секунду не должны вызывать ререндер). `motion` подключать только если понадобятся пружины/оркестрация последовательностей (например «проснулся → потянулся → помахал»); для базовых состояний хватает keyframes.

**Фаза 2 (опционально): Rive.** Если появится дизайнер — тот же контракт (`pose`, `mouthLevel`) мапится на inputs Rive State Machine, остальной код не меняется.

**Что проверено экспериментом.** SVG-персонаж и CSS для 7 состояний отрендерены в WebKit (`qlmanage`) статическими кадрами: моргание (веки `scaleY`), взмах копытом, открытый рот от `--mouth`, наклон головы + «пузырьки мысли», прыжок со звёздами, «упс» (уши в стороны, брови домиком, капля), сон (веки закрыты, Zzz). Ключевой приём — `transform-box: fill-box` + `transform-origin` в процентах, чтобы вращать SVG-группы вокруг собственных «суставов». Живая анимация SVG+CSS из раздела 3.5 проверена в Chromium 152 через локальный http-сервер (`getComputedStyle`, `document.getAnimations()`): `blink`, `breathe`, `wave`, `cheer` идут, `transform-box: fill-box` применяется, `--mouth: 0.8` даёт `matrix(1,0,0,0.8,0,0)`; про конфликт `transform` у позы `sleep` — см. примечание после CSS. `AnalyserNode` на реальном потоке OpenAI и живая анимация в Safari — **НЕ ПРОВЕРЕНЫ**.

### 2.3 Архитектура: два независимых канала

- **`pose`** (поза тела): `idle | wave | listen | think | cheer | oops | sleep`.
- **`mouth`** (0..1): живёт отдельно — Гамбит может говорить и в позе `oops`, и в `think`.

Поэтому отдельного состояния `talk` в финальной версии нет: «говорит» = `mouth > 0` + лёгкое покачивание головы поверх любой позы (в прототипе `talk` оставлен для наглядности).

Приоритеты и триггеры:

| Приоритет | Поза | Триггер (событие приложения) | Длительность |
|---|---|---|---|
| 1 | `oops` | движок: ход ребёнка хуже порога для его уровня → **до ответа бота** | пока открыт диалог «вернуть ход?» |
| 2 | `cheer` | лучший/отличный ход, найдена тактика, победа, превращение пешки | 2–2.5 с, затем возврат |
| 3 | `wave` | запуск приложения, пробуждение, прощание | 2 с |
| 4 | `listen` | `input_audio_buffer.speech_started` или нажат тумблер микрофона | пока ребёнок говорит |
| 5 | `think` | ждём движок / tool-call LLM / ответ модели | до ответа |
| 6 | `idle` | по умолчанию (дыхание, моргание раз в ~4 с, изредка взгляд на доску) | — |
| 7 | `sleep` | 60–90 с без активности / сессия закрыта / сработал лимит времени | до клика |

```ts
// mascot/poseMachine.ts — эскиз
export type Pose = 'idle'|'wave'|'listen'|'think'|'cheer'|'oops'|'sleep';
const PRIORITY: Record<Pose, number> = { oops:1, cheer:2, wave:3, listen:4, think:5, idle:6, sleep:7 };
const TRANSIENT_MS: Partial<Record<Pose, number>> = { cheer: 2400, wave: 2000 };

export function createPoseMachine(onChange: (p: Pose) => void) {
  const active = new Set<Pose>(['idle']);
  const timers = new Map<Pose, ReturnType<typeof setTimeout>>();
  const emit = () => onChange([...active].sort((a, b) => PRIORITY[a] - PRIORITY[b])[0]);
  return {
    enter(p: Pose) {
      if (p !== 'sleep') active.delete('sleep');          // любое событие будит
      active.add(p);
      const ms = TRANSIENT_MS[p];
      if (ms) { clearTimeout(timers.get(p)); timers.set(p, setTimeout(() => { active.delete(p); emit(); }, ms)); }
      emit();
    },
    leave(p: Pose) { active.delete(p); if (!active.size) active.add('idle'); emit(); },
  };
}
```

### 2.4 Рот от амплитуды WebRTC-потока

```ts
// mascot/useMouthLevel.ts — эскиз (НЕ ПРОВЕРЕНО на живой Realtime-сессии)
export function attachMouth(remote: MediaStream, audioEl: HTMLAudioElement, svgRoot: SVGSVGElement, ctx: AudioContext) {
  // 1) Воспроизведение — обычным <audio>. Так работает эхоподавление браузера, и Chromium
  //    начинает отдавать remote-stream в WebAudio (без потребителя-медиаэлемента анализатор видит тишину).
  audioEl.srcObject = remote;
  void audioEl.play();

  // 2) Анализатор — только «отвод». НЕ подключать к ctx.destination, иначе звук задвоится.
  const src = ctx.createMediaStreamSource(remote);
  const analyser = ctx.createAnalyser();
  analyser.fftSize = 512;
  src.connect(analyser);
  const buf = new Float32Array(analyser.fftSize);

  let level = 0, zeroFrames = 0, raf = 0;
  const GATE = 0.015, GAIN = 5;                     // подобрать на реальном голосе
  const tick = () => {
    analyser.getFloatTimeDomainData(buf);
    let sum = 0; for (let i = 0; i < buf.length; i++) sum += buf[i] * buf[i];
    const rms = Math.sqrt(sum / buf.length);
    zeroFrames = rms === 0 ? zeroFrames + 1 : 0;   // детектор «анализатор оглох» → включить фолбэк
    const target = Math.min(1, Math.max(0, (rms - GATE) * GAIN));
    level += (target - level) * (target > level ? 0.6 : 0.25);   // быстрая атака, медленный спад
    svgRoot.style.setProperty('--mouth', (0.12 + 0.88 * level).toFixed(3));
    raf = requestAnimationFrame(tick);
  };
  tick();
  return { stop: () => cancelAnimationFrame(raf), isDeaf: () => zeroFrames > 120 };
}
```

Подводные камни:

1. **Autoplay-политика**: `new AudioContext()` / `ctx.resume()` и `getUserMedia` — только из обработчика клика («Разбудить Гамбита»).
2. **Chromium и remote-stream**: удалённый WebRTC-поток не попадает в WebAudio, пока его не потребляет медиаэлемент — поэтому `<audio>` обязателен (если бы звук шёл через WebAudio, понадобился бы скрытый `muted <audio>`). Источник — поисковая выдача (dev.to «Browser Voice Interaction AI Pitfall Guide 2026», подтверждается вторым независимым сниппетом); баг-трекер Chromium не открыт.
3. **Эхоподавление**: не проигрывать голос модели через `ctx.destination` — в Chromium это ломает AEC (из выдачи, dev.to «Echo Cancellation with Web Audio API and Chromium»). `getUserMedia({ audio: { echoCancellation: true, noiseSuppression: true, autoGainControl: true } })`.
4. **Анализатор «глохнет»**: есть свежий баг-репорт (elevenlabs/packages #1021, Chrome Android) — `AnalyserNode` отдаёт ровно 0.0 при живом треке. Мы на desktop, но фолбэк нужен: по data-channel приходят `output_audio_buffer.started` / `output_audio_buffer.stopped` / `.cleared` (помечены «WebRTC/SIP Only» в типах `openai-node`; из веб-референса местами выпали — на форуме OpenAI подтвердили, что их «потеряли в документации»; `stopped` иногда запаздывает) → на это время включаем псевдослучайное «хлопанье» (сумма двух синусов 3.1 Гц и 7.3 Гц).
5. **`prefers-reduced-motion`**: оставить только рот и моргание.
6. Если использовать `@openai/agents-realtime@0.18.0` (MIT; по `dist/openaiRealtimeWebRtc.d.ts` из npm-тарбола): `new OpenAIRealtimeWebRTC({ audioElement, mediaStream, changePeerConnection })`: свой `<audio>` передаётся опцией `audioElement` (иначе SDK создаст элемент сам), удалённый поток затем доступен как `audioElement.srcObject`; переданный `mediaStream` микрофона SDK при `close()` не останавливает. Модель по умолчанию в SDK — `gpt-realtime-2.1`, endpoint — `https://api.openai.com/v1/realtime/calls`.
7. **Держать ссылки на узлы WebAudio** (`src`, `analyser`) и на `<audio>` в объекте/ref, а не только в локальных переменных: Chrome может собрать «висящие» узлы сборщиком мусора, и анализатор молча замолчит (dev.to Pitfall Guide 2026, из выдачи).

Апгрейд до визем (если «хлопанья» покажется мало): `wawa-lipsync@0.0.2` (MIT, 210★, последнее обновление 2025-11) или `Amoner/lipsync-engine` (MIT, 66★, не в npm, ~15 KB, `engine.attachStream(stream)`, AudioWorklet) — оба выводят виземы из частотных полос в браузере. Для мультяшного коня амплитуды достаточно («маппет-стиль»); OpenAI Realtime визем не отдаёт.

## 3. Маскот: концепты, победитель, спецификация

### 3.1 Три концепта

| | **А. Конёк «Гамбит» (Гамбитик)** | **Б. Пешка «Пешик»** | **В. Филин «Филя»** |
|---|---|---|---|
| Идея | Жеребёнок — шахматный конь на подставке. Прыгает буквой «Г», любит хитрые ходы. Старший приятель (по характеру ~10–11 лет) | Маленькая пешка, мечтает дойти до последней горизонтали и стать ферзём — как ребёнок мечтает стать мастером | Мудрый филин-тренер в очках, знает все эндшпили |
| Шахматная идентичность | Максимальная: конь — самая «живая» и узнаваемая фигура; идиома «ход конём»; имя учит термину | Высокая + сильная метафора роста | Слабая (сова «про учёбу вообще») |
| Выразительность | Уши, грива, брови, большая морда с заметным ртом, копыто для приветствия | Шар + тело: мало «органов» для эмоций, нет рук | Клюв плохо читается как говорящий рот; крылья ок |
| Сложность SVG | Средняя (проверено прототипом) | Минимальная | Средняя |
| Риск «для малышей» (NN/g) | Низкий: «прикольный приятель» | Средний: «малыш» | Низкий, но роль «учитель-взрослый» — дистанция |
| Уникальность | Высокая | Высокая | Низкая: сова Duolingo, Oliver Owl у ChessKid |
| Роль | Ровесник-наставник: «давай подумаем вместе» | Младший, которого ребёнок «ведёт» | Учитель сверху вниз |
| Итог | **Победитель** | Становится **метафорой прогресса** | Отклонён |

**Почему Гамбит:** (1) ровесник-наставник лучше подходит для просьбы «вернись и подумай» — это звучит как совет друга, а не замечание учителя; (2) самый выразительный рот/уши для голосового персонажа; (3) не выглядит «малышовым» для 9–10 лет; (4) конь даёт естественные анимации: прыжок «Г», стук копытом, уши-локаторы = «слушаю».

**Пешик остаётся в продукте** как экран прогресса «Путь пешки»: пешка ребёнка идёт со 2-й на 8-ю горизонталь (ступени программы), на 8-й — превращение в ферзя с большой церемонией, затем новая «доска» следующего уровня.

### 3.2 Характер Гамбита

- **Кто он:** жеребёнок-шахматный конь, живёт на подставке-пьедестале в правом нижнем углу. Весёлый, любопытный, чуть хвастливый («я умею перепрыгивать через фигуры!»), но честно признаёт собственные промахи («я тоже раньше зевал ферзя»).
- **Ценности:** думать перед ходом; ошибка — это находка, а не провал; хвалит *процесс* («ты проверил, что под боем, — вот это по-мастерски»), не талант («ты гений»).
- **Чего не делает никогда:** не стыдит, не сравнивает с другими детьми, не говорит «плохой ход» (говорит «этот ход что-то теряет — найдём что?»), не выдаёт длинные варианты, не придумывает оценки — только то, что дал движок через инструменты.
- **Правило трёх шагов подсказки:** вопрос («Что сейчас под боем?») → подсветка зоны/фигуры → стрелка с объяснением «почему».
- **Грамматический род:** Гамбит — «он». Это нормально сочетается с «ярким» женским тембром: в русской анимации мальчиков традиционно озвучивают актрисы.
- **Обращение к ребёнку:** по имени из профиля; пол ребёнка — поле профиля (нужно LLM для согласования глаголов: «ты нашёл / ты нашла»). Все *заготовленные* фразы ниже нейтральны по роду.

### 3.4 Режиссура голоса для realtime-модели

Факты (developers.openai.com): актуальная модель — `gpt-realtime-2.1` (модель по умолчанию в `@openai/agents-realtime@0.18.0`: `DEFAULT_OPENAI_REALTIME_MODEL = 'gpt-realtime-2.1'`). По сравнению с `gpt-realtime-2` цены и лимиты те же, лучше распознавание буквенно-цифровых строк (важно для «e4», «Nf3») и поведение при перебивании. `gpt-realtime-2`: 128k контекст, 32k max output; вход — текст/аудио/изображение, выход — текст/аудио; настраиваемый reasoning effort, function calling; только endpoint `v1/realtime`; цены: text $4 / cached $0.40 / out $24, audio in $32 / cached $0.40 / out $64, image $5 за 1M. `gpt-realtime-2` доступна и не в списке deprecations, но новые проекты начинать с 2.1; `gpt-realtime` и `gpt-realtime-mini` отключаются 2027-01-20 с миграцией на 2.1 / 2.1-mini. Есть дешёвая `gpt-realtime-2.1-mini` и отдельный full-duplex `gpt-live-1` (сравнение ниже). Все тесты голосов ниже вести на `gpt-realtime-2.1`. Голоса: `alloy, ash, ballad, coral, echo, sage, shimmer, verse, marin, cedar`; рекомендованы `marin` и `cedar`; **голос нельзя сменить после первой аудио-реплики в сессии**. Параметр скорости: `audio.output.speed`, 0.25–1.5, по умолчанию 1.0, меняется только между репликами; это пост-обработка уже сгенерированного аудио, манеру и «энергию» всё равно задают инструкции (источник: типы `openai-node`, `RealtimeAudioConfigOutput`). Там же: `voice` принимает и объект `{ id: "voice_…" }` — custom voices, но они доступны только «eligible customers» через отдел продаж, для домашнего проекта нереалистично. «Детского» голоса среди пресетов нет.

**Три варианта голосового API.**

| | `gpt-realtime-2.1` | `gpt-realtime-2.1-mini` | `gpt-live-1` |
|---|---|---|---|
| Endpoint | `v1/realtime` (WebRTC: `/v1/realtime/calls`) | то же | `v1/live/sessions` (WebRTC: аудио — медиа-треки, события — data channel) |
| Цена | audio $32 in / $64 out за 1M, text $4/$24 | audio $10 / $20, text $0.60/$2.40 | **$0.05/мин сессии, посекундно**; backend-модель и инструменты — отдельно |
| Диалог | пошаговый (VAD + перебивание) | то же | **full-duplex**: «the caller and assistant can speak at the same time» |
| «Мозг» | сама модель (reasoning effort + function calling) | то же, слабее | голосовой слой + делегирование backend-модели (Responses delegation или client delegation); function tools есть |
| Голоса | 10 пресетов (`marin`, `cedar`, …) | те же | дефолт `marin` + 12 дополнительных (quartz, ripple, vesper, willow, stone, gleam, meridian, bossa, tempo, beacon, delta, cinder) — все английские/португальские; смена голоса — только новой сессией |
| Транскрипт | `response.output_audio_transcript.delta` | то же | `session.output_transcript.delta` / `session.input_transcript.delta` **с `start_ms`/`end_ms`** — удобнее для субтитров в облачке |
| Микрофон | свой mute трека | то же | `session.input_audio.mute` / `.unmute` — ложится на тумблер «Гамбит слушает» |
| ZDR | eligible (с одобрением) | — | eligible «with limitations» |

Следствия: (а) архитектура «`pose` + `mouth` как два независимых канала» подходит и для full-duplex — там `listen` и `mouth > 0` бывают одновременно, приоритеты поз менять не нужно; (б) приём «`<audio>` + `AnalyserNode`-отвод» одинаково применим к обоим API, т.к. звук приходит WebRTC-медиатреком; фолбэк по событиям для `gpt-live-1` строится на других событиях (`output_audio_buffer.*` — это Realtime API); (в) при поминутной тарификации `gpt-live-1` правило «сон = закрытая сессия» ещё важнее: открытая сессия стоит $3/час даже в тишине; (г) `gpt-realtime-2.1-mini` — кандидат для блица и «болтовни», где глубина рассуждений не нужна (втрое дешевле по аудио). Качество русской речи у `gpt-live-1` — **НЕ ПРОВЕРЕНО** (OpenAI не публикует список языков; в обзорах упоминаются акцент и провалы беглости вне английского). Выбор между этими тремя — предмет отчёта про голос/LLM; интерфейс маскота от выбора не зависит.

**Шорт-лист для прослушивания с ребёнком:** `marin` (яркий женский — основной кандидат), `coral`, `shimmer`; мужской запасной — `ash`/`verse`. Как они звучат по-русски (акцент, ударения) — **НЕ ПРОВЕРЕНО**, нужен A/B-тест на 10 фразах из таблицы выше (на `gpt-realtime-2.1`, для сравнения цены/качества — на `gpt-realtime-2.1-mini` и `gpt-live-1`). В сообществе есть жалобы, что `gpt-realtime-2` говорит слишком медленно, и что `marin/cedar` хуже слушаются инструкций по стилю (issue openai-agents-python #1746) — из выдачи, не открыто.

Эскиз системного промпта по структуре Realtime Prompting Guide (Role & Objective → Personality & Tone → Context → Reference Pronunciations → Tools → Instructions/Rules → Conversation Flow → Safety; гайд советует короткие буллеты, примеры фраз, правило разнообразия, закрепление языка, КАПС для ключевых правил, слово «unintelligible» вместо «inaudible»; гайд написан для первого `gpt-realtime`, а не для 2.x):

```text

Ты — Гамбит, весёлый жеребёнок-шахматный конь, тренер и друг ребёнка {{name}} ({{age}} лет, обращение: {{он/она}}).
Успех = ребёнок сам находит хороший ход и хочет играть ещё.

# Личность и тон
- Голос: юный, тёплый, энергичный, с улыбкой. Как старший приятель, НЕ как учитель.
- Темп: бодрый, но чёткий. Короткие паузы между предложениями.
- Длина: 1–2 коротких предложения за раз. МАКСИМУМ 3. Одна мысль — одна реплика.

- Говори ТОЛЬКО ПО-РУССКИ, даже если слышишь другой язык или шум.

# Произношение
- Клетки читай по-шахматному: a «а», b «бэ», c «цэ», d «дэ», e «е», f «эф», g «жэ», h «аш». «e4» = «е-четыре», «Nf3» = «конь эф-три».
- Никогда не читай вслух FEN, оценки в сантипешках и длинные варианты.

- Про позицию говори ТОЛЬКО то, что вернул инструмент анализа. Если данных нет — скажи «дай-ка прикину» и вызови инструмент.
- Перед вызовом инструмента скажи короткую фразу-заполнитель («Так-так-так…»).

# Правила
- НИКОГДА не стыди, не сравнивай с другими, не говори «плохой ход» или «ошибка» в лоб.
- Хвали ПРОЦЕСС (проверил, подумал, заметил), а не талант.
- Подсказка в три шага: вопрос → куда смотреть → ход и ПОЧЕМУ.
- Не больше одной мысли о позиции за реплику; вариант не длиннее 2 ходов.
- Не повторяй одну и ту же фразу дважды подряд. Меняй слова.
- Если речь неразборчива — попроси повторить ИЛИ нажать кнопку. Не угадывай.

# Сценарий «вернуть ход» (событие blunder_detected)
«Стоп-стоп! Давай вернём ход и подумаем ещё?» → жди ответа/кнопки → если вернули: вопрос-наводка; если нет: «Твоё решение! Разберём после партии».

# Безопасность
- Не спрашивай фамилию, адрес, школу, телефон. Если ребёнок сам рассказывает личное — мягко верни к шахматам.
- Вопросы не про шахматы: один добрый короткий ответ и «вернёмся к доске?».
- Если ребёнок расстроен или говорит о чём-то тревожном — посочувствуй и предложи позвать маму или папу.
```

> **Почему `translate` / `rotate`, а не `transform`.** Если `breathe` анимирует `transform`, а поза `sleep` задаёт наклон тоже через `transform: rotate(10deg) translateY(6px)`, анимация затирает статический `transform`: спящая голова каждые 4.5 с «выпрямляется» с 10° до 0° и обратно (замерено в Chromium 152 через `getComputedStyle`: sin угла 0.17 → 0.002 → 0.17). Ещё одно наблюдение: по окончании `wave` рука мгновенно «прыгает» из 18° в 172° (у `#arm` нет `transition`) — добавить `transition: transform .3s` или завершающий keyframe.

## 4. Лестница из 8 ботов-персонажей

Принципы: (1) **возраст = сила** (как FunMasterMike у ChessKid) — ребёнку интуитивно понятно; (2) характер определяет **модель ошибок**, а не только глубину движка — у слабых ботов ошибки должны быть *человеческими* и *поучительными* (зевок фигуры, ранний ферзь, детский мат), чтобы ребёнок учился их наказывать; (3) реплики — добрые, без издёвок, у каждого бота после победы — маленький совет; (4) все боты доступны сразу (NN/g: детям важна свобода выбора), но подсвечен рекомендованный «в самый раз» (ожидаемый результат 40–60 %); (5) «время на подумать» у бота человеческое: 0.7–4 с (в пуле 0.3–1.5 с), никогда не мгновенно.

## 6. Поток экранов

```text
[Старт: Гамбит спит] --клик--> [Дом]
                                  |-- «Играть» --> [Время: 1 / 5 / 10] --> [Соперник: 8 карточек + цвет] --> [Партия]
                                  |                                                                            |
                                  |                                                   (конец партии) <--------+
                                  |                                                         v
                                  |                                                   [Разбор: 3 момента] --> [Итог дня / Дом]
                                  |-- «Тренировка дня» --> [Разминка: 3 задачи] --> [Урок-история] --> [Партия с заданием] --> [Разбор]
                                  |-- «Мой путь» --> [Прогресс: Путь пешки, навыки, альбом, мои партии]
                                  `-- (шестерёнка + замок) --> [Родительская панель]
```

**Старт.** Гамбит спит. Одна большая кнопка «Разбудить Гамбита» — это пользовательский жест для `AudioContext`, запроса микрофона и подъёма realtime-сессии. Гамбит просыпается → `wave` → «Привет-привет! Сыграем?».

**Дом.** Три огромные плитки (иконка + слово): «Играть», «Тренировка дня» (с отметкой «сегодня ещё не было»), «Мой путь». Недельный календарик-цель (7 кружков). Шестерёнка родителя — маленькая, в углу, за замком (удержание 3 с + пример на умножение). Без скролла.

**Выбор времени.** Три карточки: «1 минута — Молния» (ракета), «5 минут — Блиц» (молния), «10 минут — Спокойная» (черепаха, бейдж «Гамбит советует»). Голосом: «В молнии я молчу — некогда! А в спокойной помогу подумать». Родитель может скрыть 1-минутку для младшего возраста.

**Выбор соперника.** Горизонтальная лента из 8 карточек (стрелки влево/вправо — не скролл), рекомендованный — с рамкой «в самый раз». Выбор цвета: белые / чёрные / сюрприз. При выборе бота на 3+ ступени выше — Гамбит: «Дима очень сильный. Попробуем продержаться двадцать ходов?»

**Партия.** Слева/в центре — доска (квадрат = min(высота − 160 px, 720 px)). Справа колонка: карточка соперника (аватар с настроением, облачко реплики, часы), лента ходов фигурками, часы ребёнка (крупно; < 20 с — пульс + мягкий звук), кнопки: «Подсказка» (лампочка), «Вернуть ход» (стрелка назад), «Сдаться» (флажок, с подтверждением), тумблер микрофона. Гамбит — внизу справа, облачко-субтитры слева от него.

**Сценарий «вернуть ход» (ядро продукта):**

1. Ребёнок сделал ход → движок оценивает **до ответа бота** (порог падения оценки зависит от уровня ребёнка; слабым — только зевки фигур и мата).
2. Порог превышен → бот *не отвечает*, часы **ставятся на паузу**, доска слегка затемняется, Гамбит в позе `oops`: «Стоп-стоп! Давай вернём ход и подумаем ещё?»
3. Две большие кнопки: **«Вернуть ход»** / **«Оставить так»** (можно и голосом). Право решать — у ребёнка.
4. Вернул → подсказка в три шага → новый ход → если лучше: `cheer` + звезда «за размышление».
5. Оставил → «Твоё решение! Разберём после партии» → момент помечается для разбора.

| Контроль | Вмешательства тренера | Часы во время вмешательства |
|---|---|---|
| 10 мин | до 3 за партию (настраивается: 0 / 3 / без лимита) | пауза |
| 5 мин | до 1–2 | пауза |
| 1 мин | нет (только разбор после) | — |

Переключатель «Режим тренера: вкл/выкл» — на экране выбора соперника. В «турнирном режиме» (выкл) ручной возврат хода тоже отключён.

**«Думаю вслух».** 1–2 раза за партию в спокойный момент: «Расскажи, какой у тебя план?» Ответ (транскрипт) пишется в markdown-журнал рядом с номером хода и FEN — материал для тренера и родителя.

**Разбор (≤ 4 минут).** Сначала результат и **одна похвала за лучший ход ребёнка**. Затем 1–2 ключевых момента в виде мини-задач «Найди ход сильнее» (позиция из партии, до 3 попыток, подсказка в три шага). Кнопка «Переиграть с этого места» против того же бота. Финал: звёзды за усилие, наклейка (если заработана), «На сегодня отлично! Продолжим завтра?».

**Мой путь (детский прогресс).** «Путь пешки» — 8 ступеней; 4 шкалы навыков («Тактика», «Эндшпиль», «Дебют», «Стратегия», по 5 звёзд); галерея ботов с медалями и счётом; альбом наклеек; «Моя лучшая партия недели» (можно пересмотреть с комментарием Гамбита). Рейтинг — крупным числом только для старших; младшим — ступень.

## 8. Палитра и визуальное направление

**Направление: «тёплая бумага + сочные акценты».** Кремовый фон, крупные скруглённые карточки (radius 20–28 px), мягкие тени, плоская иллюстрация без градиентов и обводок, один яркий акцент на экран. Играючи, но не «вырвиглаз»: насыщенные цвета — только на интерактивном и на маскоте; фон и доска спокойные, чтобы не спорить с позицией. Никаких тёмных «геймерских» тем по умолчанию.

```css
:root{
  /* поверхности */
  --bg:#FFF8EC;         /* тёплая бумага */
  --surface:#FFFFFF;
  --surface-2:#FFF1DB;
  --ink:#26304F;        /* основной текст: 12.3:1 на --bg, 13.0:1 на белом */
  --ink-muted:#5C6685;  /* 5.4:1 на --bg */
  /* бренд */
  --primary:#5B4BDB;    /* индиго; белый текст 6.0:1 */
  --primary-deep:#4B3F9E;/* белый текст 8.4:1 */
  --sunny:#FFB238;      /* цвет Гамбита/наград; текст ТОЛЬКО --ink (7.2:1); белый нельзя (1.8:1) */
  --star:#FFD23F;       /* --ink 9.0:1 */
  /* семантика */
  --success:#3CCB9B;    /* заливка с --ink (6.3:1) */
  --success-deep:#167A58;/* с белым текстом 5.3:1 */
  --oops:#FF6B5E;       /* коралл; с --ink 4.65:1; белый нельзя (2.8:1) */
  --oops-deep:#C9372E;  /* с белым 5.2:1 */
  --info:#4DB5FF;       /* с --ink 5.8:1 */
  /* доска «Мята» */
  --sq-light:#F3EBD8; --sq-dark:#8CB8A8;
  /* форма */
  --radius-card:24px; --radius-btn:20px;
  --shadow:0 6px 0 rgba(38,48,79,.12);  /* «толстая» тень-ступенька у кнопок, как в детских играх */
  --font: "Nunito Variable", system-ui, sans-serif;
}
```

Все коэффициенты контраста выше посчитаны скриптом по формуле WCAG 2.x (sRGB → относительная яркость → (L1+0.05)/(L2+0.05)), не на глаз. Правило: на `--sunny`, `--star`, `--success`, `--oops`, `--info` текст всегда тёмный `--ink`; белый — только на `--primary*` и `*-deep`.

Кнопки: заливка + нижняя «ступенька»-тень 6 px, при нажатии кнопка «проваливается» на 4 px (тактильная метафора), звук клика. Иконки — заливные, скруглённые, 32–40 px; набор — собственные SVG или любой MIT-набор (конкретный пакет не выбран).

Движение: 150–250 мс для UI, пружинистые появления карточек, конфетти только на победу/ступень; ничего не мигает чаще 3 раз в секунду.

## 9. Доступность

- **Контраст:** текст ≥ 4.5:1 (у нас основной 12:1); крупный текст/иконки ≥ 3:1; фигуры различимы по контуру (≥ 7:1 к тёмной клетке).
- **Не только цвет:** оценки ходов — форма + цвет + звук; подсветка угрозы — кольцо + «!»; в графиках родителя — разные маркеры. Палитра подсветок: жёлтый / синий / коралл, не «красный против зелёного».
- **Движение:** `prefers-reduced-motion` → остаются рот и моргание, конфетти заменяется статичной звездой; тумблер «меньше анимации» в настройках.
- **Звук/голос:** всё, что говорит Гамбит, дублируется субтитрами; всё звуковое имеет визуальный эквивалент; приложение полностью работоспособно без микрофона и без звука (кнопки есть для каждого голосового действия).
- **Ввод:** клик-клик и drag; клавиатура: `Tab` по элементам, стрелки по клеткам, `Enter` — выбрать/пойти, `Esc` — отмена, `Z` — вернуть ход; видимое кольцо фокуса 3 px `--primary`.
- **Размер:** настройка шрифта 100 / 115 / 130 %; вёрстка в `rem`; минимальный кегль детского UI 18 px.
- **Чтение:** без КАПСА, без выключки по ширине, межстрочный 1.4–1.5, строки ≤ 45 знаков в облачке; простые слова.
- **Леворукий режим:** зеркалирование колонки с кнопками и позиции Гамбита.
- **Семантика:** `aria-label` у аватаров и кнопок-иконок; `aria-live="polite"` для облачка Гамбита; у клеток доски — «e4, белая пешка».
- **Эмоциональная безопасность:** нет красных «ПРОИГРАЛ» во весь экран; поражение — нейтральный экран + конкретный следующий шаг.

## 10. Риски и открытые вопросы

1. **Приватность ребёнка до 13 лет и OpenAI API.** Гайд «Under 18 API Guidance»: нельзя обрабатывать персональные данные детей до 13 без Zero Data Retention; нужно соблюдать COPPA/местные законы, давать возрастные дисклеймеры, фильтровать контент, иметь мониторинг. По developers.openai.com/api/docs/guides/your-data: `/v1/realtime` формально ZDR-eligible (хранение для abuse-мониторинга по умолчанию 30 дней, application state — нет), `/v1/live/sessions` — «eligible with limitations»; но ZDR включается **только после одобрения OpenAI через отдел продаж** («subject to prior approval… and acceptance of additional requirements») — для частного аккаунта на это рассчитывать нельзя. Практически: родитель сам является клиентом API и даёт согласие за ребёнка, но формально гайд остаётся в силе — решение принимает родитель. Смягчение: не передавать имя/фамилию (в промпт — только имя или прозвище), запрет на сбор личных сведений в промпте, транскрипты доступны родителю, микрофон по кнопке. Это не юридическая консультация.
2. **Голос realtime оплачивается через API** ($32/$64 за 1M аудио-токенов у `gpt-realtime-2` и `gpt-realtime-2.1`; $10/$20 у `gpt-realtime-2.1-mini`; $0.05/мин у `gpt-live-1`), подписка ChatGPT/Codex на Realtime API не распространяется (подробно — тема соседних отчётов; косвенно: в `codex-cli 0.154.0` команда `codex features list` показывает флаг `realtime_conversation` в статусе `removed` — голосового realtime-канала через подписку в CLI нет). UX-смягчение — «сон» маскота.
3. Качество русской речи и «юность» тембра у пресетных голосов (`marin`, `coral`, `shimmer`, `ash`, `verse`) и голосов `gpt-live-1` — **НЕ ПРОВЕРЕНО**; детского голоса среди пресетов нет. Жалобы на медленную речь `gpt-realtime-2` и на слабое следование стилю у `marin`/`cedar` — только сниппеты.
4. `AnalyserNode` на реальном remote-треке OpenAI (Realtime или Live) в Chrome и Safari, пороги `GATE`/`GAIN`, живая анимация маскота в Safari — **НЕ ПРОВЕРЕНО** (живая анимация проверена только в Chromium 152). Утверждение «проигрывание через `ctx.destination` ломает AEC в Chromium» — только сниппет dev.to.
5. Калибровка ботов 300–1100 Elo и длительность «тренировки дня» — проектные эвристики, отдельная инженерная задача.
6. Rive: точная помесячная (не годовая) цена Cadet; можно ли на free-плане скачать `.riv` из Community/Marketplace.
7. Поддержка `tabular-nums` в Nunito; лицензии наборов фигур `kosal`, `governor` (в COPYING.md их нет).
8. Khan Academy Kids, Сухин, детский ASR (WER), критика стриков Duolingo, UX Magazine — на уровне сниппетов/вторичных источников.
9. Применимость Under-18 Guidance к случаю «родитель сделал приложение для своего ребёнка на своём API-ключе» — юридический вопрос, не проверялся.
